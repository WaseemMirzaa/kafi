The big picture

Eight backend workstreams stand between mock and live

The mock build demos the whole product end-to-end. Going fully live in production hinges on these cross-cutting items — most of them touch several screens at once. Everything below in the screen tables ladders up to these.

C1

Security rules deny core client writes Blocked

Subscription, free-view counters, viewed-profiles and nanny stats are written by the client but rejected by firestore.rules in live.

Fix → move these writes to Cloud Functions / callables; make the client request-only.

C2

Storage upload paths don't match rules Blocked

Intro-video, documents and chat-image uploads write to paths storage.rules doesn't match → denied in live (photos are fine).

Fix → align client paths to the (already-correct) rules; add client-side size/type pre-checks.

C3

Notification inbox is never written Blocked

The bell reads the notifications collection, but Functions only send FCM push and never create inbox docs → inbox always empty in live.

Fix → every push-sending Function also writes an inbox doc; standardize the deep-link payload.

C4

No real payment (monetization) To build

No RevenueCat SDK; subscribe() just flips a flag. The correct server path (webhook + expiry enforcer) already exists but is unreachable.

Fix → integrate RevenueCat native purchase → webhook sets subscription server-side.

C5

Nanny self-approval & private-data exposure Security

Rules let a nanny write her own status/isVerified, and the whole approved-nanny doc (docs URLs, DOB, health) is world-readable to any signed-in user.

Fix → reject client writes to admin-owned fields; split private data into an owner/admin-only subcollection.

C6

Faked match scores & empty stats Partial

Apply/list match % are hardcoded (80 / 85 / 92-i·3); nanny stats (views/shortlists/rating) are never incremented in live.

Fix → compute real MatchService scores at apply & list time; Functions to maintain nanny stats.

C7

Chat not realtime + free-tier over-restricted Partial

Chat uses one-shot .get() (manual refresh), and rules require a subscription to open a thread, which contradicts the free-tier-chat spec.

Fix → switch to snapshots() streams; reconcile free-tier chat rules with the spec.

C8

Active-trial unlock never engages Partial

activeTrialNannyIds (keeps contacts open during a trial) is only set when a trial ends, never on accept — so a first trial never unlocks in live.

Fix → a trial onUpdate Function sets it on accept/active + flips nanny availability.

Sequencing

A phased build order

Fix the correctness/security blockers first (they unblock many screens at once), then make each journey functional, then chase accuracy and polish.

Phase 0

Correctness & security

Unblock live. Touches the most screens.

  • C1 — subscription/view/stat writes → server
  • C2 — align Storage upload paths
  • C5 — nanny self-approve + private data
  • C3 — notification inbox docs
Phase 1

Make both journeys work

The monetization + contact core.

  • C4 — RevenueCat → real subscription
  • Real contact reveal (callable) + tel:/wa.me/CV
  • C8 — active-trial unlock
  • C7 — free-tier chat + realtime streams
  • Real nanny-by-id (kill mock resolvers)
Phase 2

Match, stats & completeness

Make the numbers real.

  • C6 — real match at apply/list + stats Functions
  • Capture missing job fields + family photo
  • Persist references; fix edit-profile loss
  • Trial 48h + job 7-day schedulers
  • Admin: video review, sub-override, broadcast fan-out
Phase 3

Validation & parity

Hardening + spec details.

  • OTP lockout, password policy, reset account-check
  • Delete-account guards + cooldown
  • Notification settings honored server-side
  • Job-detail real fields + counters; legal versioning
